# Расшифровка полученных сообщений

## Суть
В настоящей клавиатуре пользователь нажимает «Расшифровать» после копирования сообщения в чате. Проверенный текст и отправитель появляются внутри панели. В приложении вкладка «Расшифровать» принимает вставленный шифротекст и показывает тот же результат. `CipherMessage.open` читает прежний `ckmsg1` и новый `ckmsg2`. Новые сообщения создаются в `ckmsg2`; см. [формат](../../Packages/CipherCore/FORMAT.md) и [аудит](../security-audit-2026-11-03.md).

Этап 06 слит в `main` по прямому решению пользователя (merge `026e967`) при 18/20 evals: E18 и E20 остались pending. Начало 07 не переводит их в pass и не возобновляет остановленные проверки 06. Регрессия затронутых общих сценариев входит в 07; независимые хвосты 06 сохраняются в его отчёте.

## Пользовательские истории
- Прочитать сообщение в мессенджере, не вставляя открытый текст в его поле.
- Увидеть проверенного отправителя или честное обозначение неизвестного ключа.
- Отличить повреждение, чужого получателя, новую версию и ошибку доступа.
- Закрыть результат без сохранения, вернуться к прежнему черновику.

## Критерии приёмки
- AC1: В настоящем расширении отдельная кнопка «Расшифровать», `keyboard.decrypt`, доступна при полном доступе, доступных публичных метаданных личного ключа и отсутствии текущей операции. Отдельная строка действий над редактором помещается в прежний предел панели за счёт перераспределения пространства. Выбранный получатель и непустой черновик не нужны. До нажатия нет чтения содержимого/метаданных буфера: ни при открытии, повороте, смене раскладки, ни по таймеру. Одно нажатие создаёт одну попытку чтения текстового значения. Нельзя читать `textDocumentProxy` для получения сообщения. Учебное превью остаётся тренажёром набора без доступа к буферу.
- AC2: Во время операции «Расшифровываем…», повторное действие заблокировано; одновременно шифровать нельзя. Старый результат удаляется до нового чтения. Вход фиксируется один раз: изменение буфера в процессе не переключает сообщение. «Закрыть» доступно во время ожидания и отменяет публикацию результата. Синхронная операция может завершиться до видимого кадра загрузки; гонки проверяются с управляемой задержкой.
- AC3: Поиск и проверка — ровно `CipherMessage.open(input, as: identity, contacts: contacts)`. Открывается первое `ckmsg<цифры>:` в порядке ядра, включая текст вокруг и whitespace внутри строки. Первое повреждённое/чужое/неподдерживаемое сообщение не пропускается ради следующего успешного. UI не отрезает подпись и не вводит второй парсер. После получения строки, до крипторазбора, предел входа 65536 байт UTF-8, включая текст вокруг; превышение: «Слишком большой текст для вставки: максимум 65536 байт». Ввод/вставка в приложении сверх предела отвергается целиком, прежний ввод сохранён; автоматической обрезки нет. Это отдельный предел от 4096 байт открытого текста в ядре.
- AC4: Успешный результат заменяет редактор и ряды клавиш внутри панели: заголовок «Расшифровано», отправитель, «✓ Подпись верна», точный текст с вертикальной прокруткой, «Закрыть». Контакт: «От: <полное имя>»; собственный ключ: «От: вы»; неизвестный: «От неизвестного ключа <первые 2 группы отпечатка>» и «Добавьте контакт в приложении, чтобы видеть имя». Подпись означает проверку ключа, не личности неизвестного человека. Полное имя переносится. Пробелы, Unicode и переводы строк сохраняются. Нельзя показывать часть текста до успешной проверки ядром. Под подписью обе поверхности показывают «Дата по часам отправителя: <локальные дата и время>» для `ckmsg2` и «Дата сообщения неизвестна» для `ckmsg1`. Дата `ckmsg2` зашифрована и подписана. При разнице с часами получателя строго больше 604 800 секунд над датой появляется «Сообщению больше 7 дней». Дата не подтверждает время доставки и не предотвращает повтор или перенос между чатами. При ошибке или закрытии дата и предупреждение исчезают вместе с результатом.
- AC5: Имя сопоставляется с актуальным ContactBook по полному валидированному PublicKey (обе части), не по имени, UUID или короткому отпечатку. Контакты перечитываются при запуске операции и перед показом результата. Переименование обновляет имя; удаление/замена полного ключа даёт неизвестного отправителя. Собственный полный ключ имеет приоритет. Ошибка чтения контактов не мешает проверке: неизвестный ключ и «Не удалось прочитать контакты — имя отправителя не определено»; для собственного сообщения остаётся «От: вы» без этой строки. Старый список не используется; автоматического добавления контакта нет.
- AC6: Одинаковые ошибки в обоих интерфейсах: `noMessage` → «В буфере нет зашифрованного сообщения. Скопируйте его в чате» в клавиатуре, «В тексте нет зашифрованного сообщения» в приложении; `malformed`/`tampered` → «Сообщение повреждено или подделано»; `notARecipient` → «Сообщение зашифровано не для вас»; `unsupportedVersion` → «Сообщение из более новой версии CipherKeyboard — обновите приложение». Прочая ошибка → «Не удалось расшифровать сообщение. Повторите попытку». Ни текста, ни успешной подписи в ошибках, включая ошибку после успеха. Повтор только по действию пользователя.
- AC7: Пустой буфер/нет текстового типа → noMessage. Если текстовый тип объявлен, но получить значение не удалось (включая отказ системы), → «Нет доступа к буферу обмена». Это классификация неудачного чтения, не обещание отдельного callback с причиной отказа iOS. Доказать поведение реального адаптера при разрешении и отказе, не только fake-ошибку. Нет повторных автоматических чтений/обхода отказа. В клавиатуре под ошибкой чтения подсказка: «Настройки → Приложения → CipherKeyboard → Вставка из других приложений → Разрешить. Чтение — только по нажатию.». Она нужна и при отказе, и если iOS в режиме «Спрашивать» не показывает запрос из расширения. Изменяет разрешение только сам пользователь через штатный интерфейс; приложение не меняет его автоматически. В приложении системная вставка/«Вставить» переносит только шифротекст в поле; отказ без передачи значения не заменяет прежний ввод и не запускает расшифровку. Если системная вставка не сообщает причину отмены, приложение не выдумывает её: результат не появляется, вставку можно повторить. Сообщённая ошибка использует «Нет доступа к буферу обмена».
- AC8: Без полного доступа кнопка расширения недоступна, рядом «Включите «Полный доступ» в Настройках, чтобы расшифровывать»; нет чтения буфера/общих контактов/Keychain ради этого действия. Нет ключа → «Откройте приложение CipherKeyboard, чтобы создать ключ»; недоступен/повреждён → «Ключ недоступен — откройте приложение CipherKeyboard». Расширение не создаёт и не исправляет ключи. Для статуса и повторной сверки запрашиваются только публичные метаданные Keychain. Закрытый ключ читается по действию и используется лишь после сверки с полным публичным ключом. В приложении существующие начальные экраны создания/ошибки сохраняются; временная ошибка ключа на вкладке: «Ключ недоступен — повторите попытку». Повтор — обычным нажатием «Расшифровать».
- AC9: Сессия, операция и полный личный ключ фиксируются и сверяются перед публикацией. Отзыв доступа, закрытие панели/клавиатуры, смена документа хозяина, глобус, фон хозяина, уход с вкладки или фон приложения отменяют операцию, освобождают вход и результат. Поздний callback не показывает текст после возврата и не задевает новую операцию. Смена личного ключа в активном экране: «Данные изменились — повторите расшифровку». Показанный текст скрывается при закрытии/фоне/смене документа/утрате доступа. Перед снимком приложения в переключателе задач содержимое закрывается непрозрачной защитой; после возврата результат пустой. Гарантируется очистка ссылок/UI, не физическое затирание всех копий Swift String.
- AC10: Чтение не меняет поле хозяина, выделение, курсор и черновик набора. «Закрыть» в той же активной сессии возвращает точные черновик, курсор и получателя; вход и результат просмотра удаляются. Завершение сессии очищает черновик по 05/06. Поворот сохраняет результат и допустимую позицию прокрутки, не перечитывает буфер. Во время шифрования кнопка расшифровки недоступна; расшифровка не вставляет шифротекст.
- AC11: В приложении вместо заглушки: заголовок «Расшифровать», «Вставьте зашифрованное сообщение», многострочное поле «ckmsg2:…» (принимает и `ckmsg1`), системное действие «Вставить» и основная «Расшифровать» (недоступна для пустого/пробельного ввода и во время операции). После принятой системной вставки клавиатура скрывается, чтобы кнопка «Расшифровать» сразу была доступна, а шифротекст оставался в поле. Приложение не снимает фокус при отказе, устаревшей доставке или превышении лимита. Запуск использует поле, не перечитывает clipboard. Успех заменяет ввод результатом AC4, системная клавиатура скрыта. «Закрыть» стирает вход/результат и возвращает пустой экран. Ошибка сохраняет шифротекст; редактирование убирает старую ошибку. Уход с вкладки/в фон стирает поле, результат и ошибки. Ввод без автокоррекции/предсказаний и восстановления состояния.
- AC12: Открытый текст не редактируется, не выделяется для копирования, без меню/drag/share/copy/cut. Нет записи входа/результата/данных отправителя в логи, UserDefaults, файлы, App Group, Keychain или буфер. Внешнее чтение clipboard — только явная вставка/AC1; clipboard не очищается и не перезаписывается. Расшифровка не вызывает `insertText`, `deleteBackward`, `adjustTextPosition`. Частные ключи только в Keychain и рабочих объектах памяти; сети нет. Доказательства используют синтетические сообщения. Снимки экрана, сделанные пользователем, вне гарантий.
- AC13: Портрет 375×667, 402×874, 440×956 pt; альбом 667×375, 874×402, 956×440 pt; обе темы. Предел расширения 420 pt в портрете/240 pt в альбоме без нижней safe area. Результат занимает панель, не overlay над работающими клавишами. Отправитель/ошибки и «Закрыть» доступны; длинное содержимое прокручивается, без горизонтального overflow; поле хозяина видно. В приложении постоянный таб-бар; ввод/действия прокручиваются при системной клавиатуре. Основные действия ≥44×44 pt. При accessibility XXXL содержимое доступно через прокрутку, «Закрыть» закреплена; помещение всего на одном экране не требуется.
- AC14: Русские labels; неизвестный отправитель обозначен как неизвестный. IDs `keyboard.decrypt`, `keyboard.decrypt.panel`, `keyboard.decrypt.status`, `keyboard.decrypt.sender`, `keyboard.decrypt.signature`, `keyboard.decrypt.date`, `keyboard.decrypt.ageWarning`, `keyboard.decrypt.text`, `keyboard.decrypt.close`; приложение — те же суффиксы с префиксом `decrypt`, плюс `decrypt.input`, `decrypt.paste`, `decrypt.submit`. Старые IDs/вкладки/сценарии сохранены.
- AC15: Шифротекст `ckmsg2`, реально вставленный по сценарию 06, открывается получателем и отправителем с точным текстом; третья личность получает AC6. Десять циклов успех/ошибка/закрытие с сообщением 4096 байт UTF-8 не приводят к падению, зависанию, удержанию старых экранов/операций или подмене расширения. Модельные тесты не заменяют настоящий extension и приложение.

## Состояния экрана и макет
Якоря `mockup.html`: расширение `keyboard-idle`, `keyboard-busy`, `keyboard-contact`, `keyboard-self`, `keyboard-unknown`, `keyboard-long`, `keyboard-no-message`, `keyboard-corrupt`, `keyboard-foreign`, `keyboard-version`, `keyboard-paste-error`, `keyboard-no-access`, `keyboard-no-key`, `keyboard-key-error`, `keyboard-contacts-warning`, `keyboard-changed`, `keyboard-oversize`; приложение `app-empty`, `app-input`, `app-busy`, `app-contact`, `app-self`, `app-unknown`, `app-long`, `app-no-message`, `app-corrupt`, `app-foreign`, `app-version`, `app-paste-error`, `app-key-error`, `app-contacts-warning`, `app-changed`, `app-oversize`.

Все 33 состояния — 375×667 в обеих темах. Дополнительно contact/long обоих интерфейсов — 402×874 и 440×956 в обеих темах; long обоих интерфейсов — все три альбомных размера в обеих темах. Всего 94 эталонные рамки (66 + 16 + 12). Generic failure использует геометрию corrupt с точным текстом AC6; возврат — idle/empty. Поворот и XXXL проверяются живыми переходами. Демонстрационный шифротекст макета сокращён; runtime использует полные строки.

В `keyboard-idle` уже выбрана Анна и набран допустимый черновик, поэтому обычная полоса статуса сохраняет текст этапа 06 «Готово к шифрованию». Общая памятка о стирании не заменяет этот статус; правила очистки черновика и результата остаются AC9/10/12.

## Архитектура и доказательства
Общий координатор с управляемыми read-only identity/contacts, clipboard reader, opener и session/clock зависимостями. UIKit/SwiftUI адаптеры отвечают за жизненный цикл и приватное отображение; ядро за формат/криптографию. Fixture keys, искусственные задержки/ошибки и диагностика недоступны в Release. Новые сетевые API и права не нужны. `ckmsg2` меняет конверт согласно FORMAT.md; чтение `ckmsg1` сохраняется.

Builder → независимые verifier/reviewer и security review по REVIEW.md; high требует отдельного first-time-user. Доказательства привязаны к SHA, установленным бинарникам и runtime. Перед приёмкой core, lint, Debug/Release, полный UI suite; focused rerun его не заменяет. Аудит использует известные synthetic canary/clipboard sentinel и подтверждённый доступ к проверяемым хранилищам. Native clipboard/жизненный цикл и статические картинки не подменяют друг друга. Pending 06 не переименовываются в успешные 07.

## Не входит
История, копирование открытого текста, автоматическая расшифровка/опрос буфера, поиск по переписке, запись в хозяина, сеть, изменение примитивов CryptoKit или формата `ckmsg1`, добавление контакта из сообщения, функциональность учебного превью. Защищённые поля и запрет сторонних клавиатур остаются ограничениями iOS.

## Решения, принятые без пользователя
- Без копирования открытого текста, как в исходном черновике.
- Просмотр временно заменяет раскладку; «Закрыть» возвращает черновик текущего сеанса.
- Неизвестный ключ с верной подписью остаётся неизвестным человеком.
- Ошибка контактов допускает чтение без имени, с предупреждением.
- Общий вставляемый текст ≤65536 байт; открытое сообщение ≤4096 байт.
- Отказ системной вставки не считается гарантированно доступным callback: ожидания для расширения и приложения различаются (AC7).
