# Evals: Контакты — ключи собеседников

> Контракт приёмки. Фича готова, только когда **все** evals в статусе `pass`.
> Статусы ставит только агент verifier, с доказательством. Строитель этот файл не меняет.
> Формат проверяет хук: заголовок `## E<номер> · Название [теги]`, поля `- **Ключ:** значение`.
> Типы: ui (сценарий в браузере/симуляторе/эмуляторе) · test · command · design · api. Статусы: pending · pass · fail.
> Теги: [negative] ошибки и неверный ввод · [security] права и чужие данные · [design] сравнение с макетом ·
> [mobile] узкий экран 375px (только web) · [regression] баг, который уже был.
>
> Для evals типа `test` verifier не только запускает тест, но и читает его: каждое утверждение из «Ожидается» должно быть
> отдельной проверкой (`#expect`/`#require` в Swift Testing, `XCTAssert…` в XCTest) в названном файле.
> Тест, который проходит, но не проверяет перечисленное, — `fail`.
> Тесты ядра — `Packages/CipherCore/Tests/CipherCoreTests/`, запуск `scripts/test.sh core --filter <Suite>`.
> UI-тесты — `UITests/`, запуск `scripts/test.sh ui -only-testing:CipherKeyboardUITests/<Класс>/<метод>`.
> «Песочница» — `scripts/sandbox.sh start` (печатает UDID, далее `<UDID>`), после проверки — `scripts/sandbox.sh stop`.
> «Контейнер группы» — `G=$(xcrun simctl get_app_container <UDID> dev.cipherkeyboard.app group.dev.cipherkeyboard)`; файл контактов — `$G/contacts.v1.json`.
> Запуск с аргументами — `xcrun simctl launch --terminate-running-process <UDID> dev.cipherkeyboard.app <аргументы>` после `scripts/run.sh` (или `scripts/sandbox.sh start`).
> «Тестовый ключ» — любой `PublicKey.string` чужой личности: в тестах ядра `Identity.generate().publicKey.string`; в UI-тестах — ключ, который UI-тест берёт с экрана «Мой ключ» второго запуска с `-keystore memory` (каждый запуск с памятью даёт новую личность), либо из констант `UITests/TestKeys.swift` (строитель кладёт туда 3 заранее сгенерированных валидных ключа `ckpub1:…` и их отпечатки).
> «Свой ключ» — текст элемента `mykey.publicKey` текущего запуска.

## E3 · Чужой мусор, свой ключ и дубли не попадают в книгу [negative] [security]
- **Тип:** test
- **Шаги:** `ContactBookTests.swift › rejectsBadKeysAndDuplicates`: книга с «Анна» (ключ K1), своя личность с ключом K0. Попытки: 1) строка `"привет"` 2) `"Мой ключ: " + K2` 3) K2 с заменённым последним символом (`ckpub1:…` с испорченным base64) 4) `ckpub1:` + base64url 64 байт, где X25519-часть — точка малого порядка (нулевые 32 байта) 5) `"ckpub2:" + тело K2` 6) K0 (свой) 7) K1 под именем «Аня» 8) K2 под именем «анна» 9) K1 с пробелами и переносами строки внутри под именем «Аня»

- **Статус:** pass
