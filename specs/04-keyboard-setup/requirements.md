# Подключение клавиатуры

## Суть
Экран «Настройка» в приложении ведёт пользователя через подключение CipherKeyboard в Настройках iOS и включение «Полного доступа», честно объясняет, зачем он нужен, и показывает, что уже сделано.

## Пользовательские истории
- Как новый пользователь, я хочу пошагово понять, как добавить клавиатуру, не ища инструкцию в интернете.
- Как осторожный пользователь, я хочу понять, зачем клавиатуре «Полный доступ» и что она не отправляет мои данные.

## Критерии приёмки
- AC1: Клавиатура не добавлена → на экране «Настройка» шаги: «1. Откройте Настройки → Приложения → CipherKeyboard → Клавиатуры», «2. Включите CipherKeyboard», «3. Включите «Полный доступ»», четвёртый шаг: «Откройте поле ввода в любом приложении, удерживайте 🌐 и выберите CipherKeyboard»; кнопка «Открыть Настройки» (публичный переход в настройки приложения; на iOS 27 может открыться общий экран).
- AC2: Клавиатура добавлена, но ни разу не открывалась с полным доступом → «Включите «Полный доступ» и откройте клавиатуру в любом приложении».
- AC3: После успешного открытия расширения с полным доступом → «Подключение проверено» с галочкой и текстом «Полный доступ был включён при последнем открытии клавиатуры. Если вы меняли настройки, откройте клавиатуру снова». Инструкции доступны по кнопке «Показать шаги». Это историческое подтверждение, не гарантия текущего разрешения.
- AC4: Блок «Зачем полный доступ»: клавиатуре нужны ваши ключи и контакты из приложения и доступ к скопированному шифротексту; «CipherKeyboard не подключается к интернету и ничего никуда не отправляет».
- AC5: Состояние обновляется при возврате в приложение, без перезапуска.
- AC6: Пока клавиатура не готова, на вкладке «Мой ключ» есть баннер «Проверьте подключение клавиатуры» со ссылкой на «Настройка».
- AC7: В самой клавиатуре без полного доступа — баннер «Включите «Полный доступ» в Настройках, чтобы шифровать» Кнопка 🌐 работает; раскладки и набор текста появятся в 05, в этом этапе их не реализуем.

## Состояния экрана
- Не добавлена; добавлена без полного доступа / ещё не открывалась; подключение проверено ранее.
- Баннер на «Мой ключ».
- Баннер внутри клавиатуры без полного доступа.

## Граничные случаи
- Пользователь выключил полный доступ после настройки — расширение при следующем показе проверяет hasFullAccess и показывает запрет. Приложение не выдаёт старую отметку за текущее разрешение: остаётся пояснение о последней проверке. Без доступа расширение не обязано иметь возможность стереть отметку в App Group.
- Пользователь удалил клавиатуру из списка — экран возвращается к шагу 1.
- Системный язык английский — тексты всё равно русские (локализации в MVP нет).

## Не входит
- Видео и анимации инструкции, локализация.

## Решения, принятые без пользователя
- «Добавлена» определяется по списку активных клавиатур системы; «полный доступ был при последнем успешном показе» — по отметке, которую клавиатура пишет в общий контейнер при запуске (без полного доступа она туда писать не может).
- Кнопка ведёт в настройки приложения (`UIApplication.openSettingsURLString`) — открыть сразу раздел клавиатур iOS не даёт.

## Дополнительные критерии
- AC8: Нет списка активных клавиатур или его формат неизвестен → «Не удалось проверить подключение», инструкции остаются доступны. Отсутствие данных не равно «не добавлена». Сравнивается точный идентификатор расширения, без совпадений по подстроке. При подтверждённом удалении клавиатуры старая отметка сбрасывается приложением; повторное добавление требует нового показа расширения.
- AC9: Общая запись содержит только версию и время успешного показа расширения с hasFullAccess=true; никаких ключей, контактов, ввода, буфера. Нечитаемая, неизвестная или будущая отметка не подтверждает подключение. Ошибка записи не мешает 🌐 и не меняет ключи/контакты.
- AC10: Ошибка открытия настроек → «Не удалось открыть Настройки» и ручной путь «Настройки → Основные → Клавиатура → Клавиатуры». Без частных URL-схем. Все тексты русские, обе темы, 375×667 и 402×874, элементы управления ≥44 pt, прокрутка без перекрытия таб-баром.
- AC11: Debug-инъекции состояния доступны только для UI-тестов; в Release отсутствуют. Проверки на реальном расширении обязательны помимо инъекций.

## Техническая проверка перед реализацией
Список активных клавиатур требует отдельной проверки на целевых iOS: недокументированный ключ настроек нельзя считать надёжным публичным API. При невозможности определить список используется честное неопределённое состояние AC8. Текущее разрешение определяет только реальное расширение через [hasFullAccess](https://developer.apple.com/documentation/uikit/uiinputviewcontroller/hasfullaccess). Нельзя создавать фиктивный UIInputViewController в приложении ради проверки разрешения.
