# Evals: Мой ключ — создание, хранение, показ

> Контракт приёмки. Фича готова, только когда **все** evals в статусе `pass`.
> Статусы ставит только агент verifier, с доказательством. Строитель этот файл не меняет.
> Формат проверяет хук: заголовок `## E<номер> · Название [теги]`, поля `- **Ключ:** значение`.
> Типы: ui (сценарий в браузере/симуляторе/эмуляторе) · test · command · design · api. Статусы: pending · pass · fail.
> Теги: [negative] ошибки и неверный ввод · [security] права и чужие данные · [design] сравнение с макетом ·
> [mobile] узкий экран 375px (только web) · [regression] баг, который уже был.
>
> Для evals типа `test` verifier не только запускает тест, но и читает его: каждое утверждение из «Ожидается» должно быть
> отдельной проверкой (`#expect`/`#require` в Swift Testing, `XCTAssert…` в XCTest) в названном файле.
> Тест, который проходит, но не проверяет перечисленное, — `fail`.
> Тесты ядра — `Packages/CipherCore/Tests/CipherCoreTests/`, запуск `scripts/test.sh core --filter <Suite>`.
> UI-тесты — `UITests/`, запуск `scripts/test.sh ui -only-testing:CipherKeyboardUITests/<Класс>/<метод>`.
> «Песочница» — `scripts/sandbox.sh start` (печатает UDID, далее `<UDID>`), после проверки — `scripts/sandbox.sh stop`.
> «Keychain песочницы» — `~/Library/Developer/CoreSimulator/Devices/<UDID>/data/Library/Keychains/keychain-2-debug.db`;
> запрос `KC` = `sqlite3 <db> "select agrp, pdmn, sync from genp where agrp='group.dev.cipherkeyboard'"`
> (`pdmn = aku` — это `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`).
> Запуск с аргументами — `xcrun simctl launch --terminate-running-process <UDID> dev.cipherkeyboard.app <аргументы>` после `scripts/run.sh` (или `scripts/sandbox.sh start`).
> «Ключ на экране» — текст элемента `mykey.publicKey`; «отпечаток на экране» — текст `mykey.fingerprint`.

## E1 · Первая загрузка создаёт личность, вторая — читает ту же
- **Тип:** test
- **Шаги:** автотест `IdentityStoreTests.swift › IdentityStoreTests` (`scripts/test.sh core --filter IdentityStoreTests`), хранилище — поддельный `SecretStorage` в памяти, который считает вызовы `read`/`add`
- **Ожидается:** тест проходит и проверяет: на пустом хранилище `loadOrCreate()` возвращает личность, `add` вызван ровно 1 раз с данными длиной 64 байта, и `Identity(privateKeyData: <эти данные>).publicKey` равен ключу возвращённой личности; повторный `loadOrCreate()` на том же хранилище возвращает личность с тем же `publicKey`, `add` больше не вызывается (всего 1); новый `IdentityStore` поверх того же хранилища (имитация перезапуска) тоже возвращает тот же `publicKey`; два разных пустых хранилища дают разные `publicKey`
- **Почему провалит плохую работу:** ловит пересоздание ключа при каждом запуске, кэш личности в памяти вместо хранилища, запись только половины ключа (32 байта) и захардкоженную личность
- **Статус:** pass
- **Доказательство:** ц2r4: scripts/test.sh core: «121 tests in 21 suites passed»; Packages/ и Keyboard/ в раунде не менялись (git diff --stat f60c68f 532f045: только App/RootView.swift)

## E2 · Ошибка чтения Keychain не создаёт новый ключ [negative] [security]
- **Тип:** test
- **Шаги:** автотест `IdentityStoreTests.swift › IdentityStoreTests` — поддельное хранилище, в котором уже лежит запись личности A, а `read` возвращает по очереди каждый из статусов: `errSecInteractionNotAllowed`, `errSecMissingEntitlement`, `errSecAuthFailed`, `errSecParam`, `-1`
- **Ожидается:** тест проходит и проверяет для каждого статуса (параметризованно): `loadOrCreate()` бросает ошибку «хранилище недоступно» с этим статусом; `add` не вызван ни разу; в поддельном хранилище по-прежнему ровно запись A, байт в байт; затем `read` начинает отвечать нормально — `loadOrCreate()` возвращает личность с `publicKey == A.publicKey`. Отдельно: запись есть, но её длина 0, 63 или 65 байт → `loadOrCreate()` бросает ошибку, `add` не вызван, запись не изменена
- **Почему провалит плохую работу:** ловит самую опасную халтуру — «не прочитали → создали новый» (`try?` вокруг чтения, `if data == nil { generate() }`): на заблокированном телефоне старый ключ молча заменился бы новым, и все прошлые сообщения не прочитать
- **Статус:** pass
- **Доказательство:** ц2r4: scripts/test.sh core: «121 tests in 21 suites passed»; Packages/ и Keyboard/ в раунде не менялись (git diff --stat f60c68f 532f045: только App/RootView.swift)

## E3 · Одновременное создание не перезаписывает ключ [negative]
- **Тип:** test
- **Шаги:** автотест `IdentityStoreTests.swift › IdentityStoreTests` — поддельное хранилище: первый `read` → `errSecItemNotFound`; `add` → `errSecDuplicateItem` и в этот момент в хранилище появляется запись личности B (её записал «другой запуск»); следующий `read` возвращает B. Второй случай: `add` → `errSecIOErr`
- **Ожидается:** тест проходит и проверяет: в первом случае `loadOrCreate()` возвращает личность с `publicKey == B.publicKey`, запись B в хранилище не изменена, у поддельного хранилища нет вызовов `update`/`delete` (их нет и в протоколе `SecretStorage`); во втором случае `loadOrCreate()` бросает ошибку «хранилище недоступно» со статусом `errSecIOErr`, а не возвращает несохранённую личность
- **Почему провалит плохую работу:** ловит «удалить и записать заново» при дубликате (затирает чужой только что созданный ключ) и возврат личности, которая не сохранилась — пользователь раздаст ключ, который пропадёт после перезапуска
- **Статус:** pass
- **Доказательство:** ц2r4: scripts/test.sh core: «121 tests in 21 suites passed»; Packages/ и Keyboard/ в раунде не менялись (git diff --stat f60c68f 532f045: только App/RootView.swift)
