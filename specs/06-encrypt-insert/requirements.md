# Шифрование и вставка в сообщение

## Суть
В настоящей клавиатуре пользователь выбирает контакт и нажимает «Зашифровать». Готовая строка `ckmsg1:…` вставляется в поле хозяина; отправляет её сам пользователь. Криптография и формат остаются в CipherCore. При ошибке открытый текст никогда не служит запасным вариантом.

## Пользовательские истории
- Зашифровать внутренний черновик для выбранного собеседника и себя, не раскрывая текст мессенджеру.
- Видеть выбранного получателя и безопасно исправить ошибку без потери текущего черновика.

## Критерии приёмки
- AC1: Над черновиком строка «Кому: выберите контакт ▾» либо «Кому: <имя> ▾», рядом кнопка «Зашифровать». Список открывается внутри панели без второй клавиатуры, повторяет порядок ContactBook, показывает полное имя и короткий отпечаток. Выбранный контакт отмечен. «Назад» закрывает список без смены выбора; выбор строки закрывает список, сохраняет черновик и курсор. Длинное имя в строке выбора допускает сокращение, полное доступно в списке и accessibility label.
- AC2: Запоминается только UUID последнего явно выбранного контакта, локально в настройках расширения, при полном доступе. Нельзя запоминать имя, ключ, черновик или шифротекст. При первом запуске автоматического выбора нет, даже если контакт один. При открытии сессии/списка и перед шифрованием контакты перечитываются. Удалённый или отсутствующий id сбрасывается; пустой список: «Добавьте контакт в приложении CipherKeyboard». Ошибка чтения: «Не удалось прочитать контакты» и кнопка «Повторить»; устаревший список не используется для шифрования.
- AC3: Кнопка доступна только при полном доступе, доступном личном ключе, актуальном выбранном контакте и непустом после проверки whitespacesAndNewlines черновике в пределах 4096 байт UTF-8. Проверка пробелов не меняет сам текст: ведущие/хвостовые пробелы, переводы строк и Unicode шифруются точно. Набор остаётся доступен при пустых/ошибочных хранилищах и без доступа.
- AC4: Нажатие фиксирует текст, курсор, id и полный ключ получателя, личный ключ, текущую сессию и документ хозяина. Перед передачей результата повторно проверяются полный доступ, актуальность сессии/документа, контакта и личного ключа. Изменение ключа под прежним id, его удаление или смена личности отменяет операцию, сбрасывает выбор; «Данные изменились — выберите получателя заново». Одно переименование с тем же id и полным ключом обновляет имя без изменения адресата. После изменения ключа в открытой панели требуется явный повторный выбор, включая изменения, обнаруженные до начала операции. Короткий отпечаток не применяется для проверки равенства ключей.
- AC5: В хозяина передаётся ровно одна готовая непустая строка `ckmsg1:…`, без подписи, пробелов, многоточия или перевода строки. Единственный изменяющий вызов — `insertText(ciphertext)`; никаких deleteBackward/adjustTextPosition/предварительных вставок. При пустом выделении вставка происходит в позицию курсора, существующий текст до и после сохраняется. При непустом выделении: 0 вставок, «Снимите выделение в поле сообщения», черновик сохранён; выделение и текст хозяина не меняются. Контекст хозяина не читается ради поиска/обработки текста; разрешены только проверки выделения и идентичности документа для безопасной вставки.
- AC6: После возврата из единственного вызова вставки черновик и курсор очищаются. В постоянной полосе состояния на 2 секунды «Зашифровано для <имя>», затем обычный статус. Получатель остаётся выбранным. Изменение плашки не двигает редактор/клавиши; полное имя доступно VoiceOver. Нет автоматической отправки, чтения результата вставки, повтора при новом открытии или копирования в буфер. Возврат insertText не является подтверждением доставки или отправки сообщения.
- AC7: В ходе операции состояние «Шифруем…», повторное нажатие, набор и смена получателя заблокированы; зафиксированный текст не может поменяться. Два быстрых нажатия дают 1 вставку. Пока операция не завершена, второй независимой операции нет. Короткая синхронная операция может завершиться до видимого кадра загрузки, но состояние проверяется с управляемой задержкой. Следующий новый черновик можно зашифровать обычным новым нажатием.
- AC8: Нет ключа: «Откройте приложение CipherKeyboard, чтобы создать ключ». Ошибка Keychain: «Ключ недоступен — откройте приложение CipherKeyboard». Прочая ошибка шифрования: «Не удалось зашифровать сообщение. Повторите попытку»; действие — новое нажатие «Зашифровать» после устранения причины. Во всех ошибках до вставки 0 вызовов proxy, текст и курсор сохраняются в активной сессии. Расширение не создаёт и не пересоздаёт ключи.
- AC9: Сохраняется предел ввода этапа 05: операция набора свыше 4096 байт отвергается целиком с прежним сообщением «Сообщение не должно превышать 4096 байт». При N > 3500 в постоянном месте «N / 4096 байт», при N ≤ 3500 счётчик скрыт без скачка геометрии. Защитная проверка шифрования независимо отклоняет текст 4097+ байт: «Слишком длинное сообщение: N из 4096 байт», 0 вставок, текст и курсор сохранены. Этот случай вводится через тестовую зависимость, а не через обход лимита в Release UI.
- AC10: Вставленную строку открывают реальным CipherMessage.open выбранный получатель и отправитель; получают точный исходный текст и проверенный полный ключ отправителя. Третий ключ получает notARecipient. При наличии отправителя в контактах получателя возвращается соответствующий контакт, иначе unknown. Подмена байта, подписи или ключа отправителя отклоняется. Проверка не зависит от ещё не реализованного UI этапа 07.
- AC11: Без полного доступа баннер «Включите «Полный доступ» в Настройках, чтобы шифровать», выбор и шифрование недоступны, общие хранилища/запомненный выбор не читаются и не записываются. Отзыв доступа до вставки даёт 0 вставок. Приватные ключи хранятся только в Keychain; рабочие объекты ключей используются только в памяти. Черновик/шифротекст не пишутся в UserDefaults, Keychain, файлы, App Group, clipboard или логи. Шифротекст покидает клавиатуру только через явное нажатие и единственную вставку.
- AC12: Закрытие клавиатуры, фон хозяина или переключение через глобус стирают черновик, отменяют незавершённую операцию, освобождают временные объекты; её отложенный результат не вставляется после возврата. Смена документа до вставки отменяет её без переноса результата в новое поле; при сохранении активной сессии черновик остаётся и показано «Поле сообщения изменилось — повторите попытку». Если вставка уже вызвана, после возврата черновик очищен, автоматического повтора нет. Поворот активного сеанса сохраняет черновик/получателя и не создаёт второй операции. Нельзя обещать транзакционность при принудительном завершении процесса iOS; гарантируется отсутствие частичных вызовов со стороны расширения.
- AC13: Портрет 375×667, 402×874, 440×956 pt и альбом 667×375, 874×402, 956×440 pt, обе темы. Панель не больше 420 pt в портрете и 240 pt в альбоме без нижней safe area, как в 05. В портрете редактор растёт от одной до четырёх видимых строк, затем прокручивается; в альбоме видна одна строка. В альбоме редактор/получатель и клавиши могут занимать две колонки. Все четыре ряда видны, редактор прокручивается, поле хозяина видно; выбор контакта/шифрование/повтор/назад имеют область ≥44×44 pt, буквенные клавиши сохраняют согласованные исключения 05 (ширина ≥26 pt, высота ≥44 портрет/32 альбом). Список прокручивается, строки ≥44 pt. Нет наложений, обрезанных ошибок или горизонтального переполнения. Проверить реальный переход от пустого к многострочному вводу, открытие/закрытие списка и смену статусов.
- AC14: Русские accessibility labels, выбранный контакт/недоступность/загрузка объявлены; keyboard.recipient, keyboard.recipient.list, keyboard.recipient.<UUID>, keyboard.recipient.back, keyboard.encrypt, keyboard.encrypt.status, keyboard.contacts.retry. Старые идентификаторы ввода сохраняются. Смена раскладок, удаление, жесты, глобус, приватность и жизненный цикл из 05 работают. Превью в приложении остаётся тренажёром набора с read-only полем «До встречи!»; новые выбор/шифрование доступны только в настоящем расширении. После 10 циклов выбора/вставки/закрытия и 4096-байтового сообщения нет зависаний, падения или подмены клавиатуры системной.

## Архитектура и доказательства
Координатор операции отделён от модели приватного ввода; только он имеет узкую возможность передать готовый шифротекст адаптеру хозяина. Управляемые reader/sealer/clock/session/document зависимости нужны для воспроизводимых гонок/ошибок; тестовые источники данных не доступны в Release. Получатель проверяется по UUID и полному валидированному PublicKey, включая обе части; криптография вызывается через CipherCore, без собственного формата/алгоритма.

Проверить модель со spy proxy и настоящий установленный extension в Debug-хозяине и обычном приложении симулятора. Зафиксировать SHA, хеш установленного бинарника и runtime revision. Аудит приватности: известный синтетический clipboard sentinel, непустая известная identity и подтверждённая видимость её метаданных; сравнить логи/файлы/настройки/Keychain metadata до и после успешного и ошибочного сценариев. Реальные сообщения/секреты в доказательства не включать. Перед приёмкой полный UI suite, core, lint, Debug/Release, аудит бинарников/entitlements, независимые verifier/reviewer + security review, first-time-user и приёмка человеком.

## Не входит
UI расшифровки (07), автоматическая отправка, несколько внешних получателей, история, сеть, буфер обмена, сохранение/восстановление черновика, изменение формата ckmsg1, изменение учебного превью. Защищённые поля и приложения, запрещающие сторонние клавиатуры, остаются ограничениями iOS.

## Решения для согласования
- Вставлять только техническую строку ckmsg1 без дополнительной подписи; себя добавляет ядро.
- Запоминать только id контакта; после смены ключа требовать явный выбор.
- Не заменять выделенный текст хозяина: показать просьбу снять выделение.
- Кнопка шифрования рядом с выбором получателя; компактный альбом в две колонки; прежние пределы высоты панели сохраняются.
- Превью остаётся только для набора; round-trip этапа 06 проверяется через ядро до UI этапа 07.
