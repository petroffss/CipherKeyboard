# Evals: Крипто-ядро — ключи, шифрование, подпись

> Контракт приёмки. Фича готова, только когда **все** evals в статусе `pass`.
> Статусы ставит только агент verifier, с доказательством. Строитель этот файл не меняет.
> Формат проверяет хук: заголовок `## E<номер> · Название [теги]`, поля `- **Ключ:** значение`.
> Типы: ui (сценарий в браузере/симуляторе/эмуляторе) · test · command · design · api. Статусы: pending · pass · fail.
> Теги: [negative] ошибки и неверный ввод · [security] права и чужие данные · [design] сравнение с макетом ·
> [mobile] узкий экран 375px (только web) · [regression] баг, который уже был.
>
> Для evals типа `test` verifier не только запускает тест, но и читает его: каждое утверждение из «Ожидается» должно быть
> отдельной проверкой `#expect`/`#require` в названном файле. Тест, который проходит, но не проверяет перечисленное, — `fail`.
> Все тесты лежат в `Packages/CipherCore/Tests/CipherCoreTests/`, запуск — `scripts/test.sh core --filter <Suite>`.
> A, B, C, M — разные личности из `Identity.generate()`, если не сказано иное.
