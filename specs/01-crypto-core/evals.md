# Evals: Крипто-ядро — ключи, шифрование, подпись

> Контракт приёмки. Фича готова, только когда **все** evals в статусе `pass`.
> Статусы ставит только агент verifier, с доказательством. Строитель этот файл не меняет.
> Формат проверяет хук: заголовок `## E<номер> · Название [теги]`, поля `- **Ключ:** значение`.
> Типы: ui (сценарий в браузере/симуляторе/эмуляторе) · test · command · design · api. Статусы: pending · pass · fail.
> Теги: [negative] ошибки и неверный ввод · [security] права и чужие данные · [design] сравнение с макетом ·
> [mobile] узкий экран 375px (только web) · [regression] баг, который уже был.
>
> Для evals типа `test` verifier не только запускает тест, но и читает его: каждое утверждение из «Ожидается» должно быть
> отдельной проверкой `#expect`/`#require` в названном файле. Тест, который проходит, но не проверяет перечисленное, — `fail`.
> Все тесты лежат в `Packages/CipherCore/Tests/CipherCoreTests/`, запуск — `scripts/test.sh core --filter <Suite>`.
> A, B, C, M — разные личности из `Identity.generate()`, если не сказано иное.

## E1 · Личность создаётся и восстанавливается из приватных данных
- **Тип:** test
- **Шаги:** автотест `IdentityTests.swift › IdentityTests` (`scripts/test.sh core --filter IdentityTests`)
- **Ожидается:** тест проходит и проверяет: две `Identity.generate()` дают разные `publicKey` и разные `fingerprint`; `privateKeyData().count == 64`; `Identity(privateKeyData: a.privateKeyData()).publicKey == a.publicKey`; восстановленная личность расшифровывает сообщение, зашифрованное для исходной; `Identity(privateKeyData:)` из 0, 63 и 65 байт бросает ровно `CipherError.invalidKey`
- **Почему провалит плохую работу:** ловит одну пару ключей вместо двух, неполный экспорт (только X25519 — подпись после восстановления другая) и молчаливое создание новой личности из битых данных вместо ошибки (потеря ключа в 02)
- **Статус:** pending
- **Доказательство:** —

## E2 · Открытый ключ выгружается в строку ckpub1 и разбирается обратно
- **Тип:** test
- **Шаги:** автотест `PublicKeyTests.swift › PublicKeyTests` (`scripts/test.sh core --filter PublicKeyTests`)
- **Ожидается:** тест проходит и проверяет: `publicKey.string` соответствует `^ckpub1:[A-Za-z0-9_-]{86}$` (93 символа); `PublicKey(string: k.string) == k`; разбирается та же строка с пробелом после двоеточия, с `\n` каждые 20 символов, с неразрывным пробелом `\u{00A0}` внутри `ckpub1`, с паддингом `==` на конце — каждый раз ключ равен исходному; JSON-кодирование `PublicKey` через `JSONEncoder` даёт строку `"ckpub1:…"` и декодируется обратно в равный ключ; фиксированный вектор: личность из захардкоженных 64 байт `privateKeyData` (hex-литерал в тесте) даёт захардкоженную строку `ckpub1:…` и захардкоженный отпечаток (литералы, не вычисленные кодом)
- **Почему провалит плохую работу:** ловит base64 вместо base64url, паддинг на выходе, ключ из одной публичной части, «обрезку пробелов только по краям» и вектор, сверенный сам с собой
- **Статус:** pending
- **Доказательство:** —

## E3 · Отпечаток считается ровно по спецификации — независимая проверка
- **Тип:** command
- **Шаги:** 1) взять из `PublicKeyTests.swift` литералы фиксированного вектора: строку `ckpub1:…` и отпечаток 2) выполнить `python3 -c 'import base64,hashlib,sys; s=sys.argv[1]; b=base64.urlsafe_b64decode(s[7:]+"="*(-len(s[7:])%4)); print(len(b)); h=hashlib.sha256(b).hexdigest().upper()[:32]; print(" ".join(h[i:i+4] for i in range(0,32,4)))' '<строка ckpub1>'` 3) сравнить со значением из теста 4) убедиться, что тест `PublicKeyTests` проходит и проверяет `fingerprint.short` = первые 9 символов отпечатка
- **Ожидается:** первая строка вывода — `64`; вторая — 39 символов, 8 групп по 4 hex в верхнем регистре через пробел, совпадает с литералом отпечатка в тесте символ в символ
- **Почему провалит плохую работу:** ловит отпечаток только от ключа подписи, SHA-256 от строки вместо байтов, нижний регистр, другое число байт — то, что тест, написанный тем же строителем, пропустил бы
- **Статус:** pending
- **Доказательство:** —

## E4 · Неверный открытый ключ не принимается [negative] [security]
- **Тип:** test
- **Шаги:** автотест `PublicKeyTests.swift › InvalidPublicKeyTests` (`scripts/test.sh core --filter InvalidPublicKeyTests`)
- **Ожидается:** тест проходит и проверяет точную ошибку для каждого ввода: `""` → `invalidKey`; `"ckpub1:"` → `invalidKey`; ключ без последнего символа → `invalidKey`; ключ с лишним символом → `invalidKey`; `"Мой ключ: " + k.string` → `invalidKey`; `"ckpkx1:" + тело` → `invalidKey`; строка `ckmsg1:…` из `seal` → `invalidKey`; последний символ заменён так, что меняются только неиспользуемые биты (неканонический base64) → `invalidKey`; часть X25519 из 32 нулевых байт (корректный base64url) → `invalidKey`; часть X25519 = точка малого порядка `0100…00` (байт 1 и 31 нулевой байт) → `invalidKey`; такой ключ нельзя передать в `seal` — его просто невозможно получить; `"ckpub2:" + тело` → `unsupportedVersion`

## E12 · Отправителя нельзя подменить [security]
- **Тип:** test
- **Шаги:** автотест `TamperTests.swift › SenderSpoofTests` (`scripts/test.sh core --filter SenderSpoofTests`); тест может использовать `@testable import CipherCore` для сборки подделок из полей формата
- **Ожидается:** тест проходит и проверяет для `m = seal(t, from: A, to: [B])`: 1) подпись в `m` заменена подписью M над теми же подписываемыми байтами, ключ отправителя оставлен A → `open` как B бросает `tampered`; 2) ключ отправителя заменён ключом M, подпись пересчитана ключом M над изменёнными байтами → `open` как B бросает `tampered` (не возвращает текст с отправителем M); 3) подпись в `m` заменена 64 нулевыми байтами → `tampered`; 4) честное сообщение `seal(t, from: M, to: [B])` с контактами B `[A]` даёт `.unknown(M.publicKey.fingerprint)`, а не `.contact(A)`

- **Статус:** pending
- **Доказательство:** —

## E17 · FORMAT.md совпадает с реальными байтами
- **Тип:** command
- **Шаги:** 1) прочитать `Packages/CipherCore/FORMAT.md` 2) по описанной там раскладке написать в песочнице verifier'а короткий скрипт на Python, который декодирует золотой вектор из `GoldenVectorTests.swift` (`base64.urlsafe_b64decode`) и разбивает байты на поля 3) сравнить поле «ключ отправителя» с 64 байтами, декодированными из `A.publicKey.string` (литерал или вывод теста), а число записей получателей — с 2 (B и A)
- **Ожидается:** FORMAT.md существует и описывает `ckpub1` и `ckmsg1`: поля, их длины в байтах и порядок, кодировку длины/числа записей, что покрывает подпись, что входит в AAD, порядок проверок при разборе (формат → подпись → запись получателя → расшифровка); сумма длин полей по FORMAT.md равна длине декодированного вектора; поле ключа отправителя совпадает с ключом A байт в байт; записей получателей ровно 2
- **Почему провалит плохую работу:** ловит документацию, написанную «для галочки» и разошедшуюся с кодом, — без неё следующую версию формата нельзя сделать совместимой
- **Статус:** pending
- **Доказательство:** —

## E18 · Ядро не логирует, не пишет на диск и не выдаёт CryptoKit наружу [security]
- **Тип:** command
- **Шаги:** 1) `grep -rnE 'print\(|debugPrint\(|Logger|os_log|NSLog|UserDefaults|FileManager|UIPasteboard|URLSession|import Network|\.write\(to' Packages/CipherCore/Sources` 2) `grep -rnE '^\s*public .*\b(Curve25519|SymmetricKey|ChaChaPoly|SharedSecret|SHA256Digest|HKDF|P256)\b' Packages/CipherCore/Sources` 3) `grep -rn 'import CryptoKit' App Keyboard` 4) `scripts/lint.sh; echo "lint exit=$?"`
- **Ожидается:** команды 1–3 ничего не выводят; команда 4 печатает `lint exit=0`
- **Почему провалит плохую работу:** ловит отладочный `print` открытого текста или ключа, оставленный в ядре, запись во временный файл, публичные свойства с типами CryptoKit (приложение начнёт собирать криптографию само) и `import CryptoKit` в приложении или клавиатуре
- **Статус:** pending
- **Доказательство:** —

## E19 · Все тесты ядра зелёные, приложение и клавиатура собираются
- **Тип:** command
- **Шаги:** 1) `scripts/test.sh core 2>&1 | tail -20` 2) `mkdir -p .build && scripts/build.sh > .build/ck-build.log 2>&1; echo "build exit=$?"; tail -5 .build/ck-build.log` 3) `grep -iE 'warning: .*(Sendable|concurrency|data race)' .build/ck-build.log`
- **Ожидается:** в выводе 1 все тесты пройдены, 0 упавших, в том числе все суиты из E1–E16 и прежний `SmokeTests`; вывод 2 — `build exit=0`; команда 3 ничего не выводит

- **Статус:** pending
- **Доказательство:** —
