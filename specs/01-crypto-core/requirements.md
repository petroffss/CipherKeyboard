# Крипто-ядро — ключи, шифрование, подпись

## Суть
Библиотека `CipherCore` (`Packages/CipherCore`): создать личность (пару ключей), выгрузить открытый ключ в текст и разобрать обратно, зашифровать текст для получателей с подписью отправителя, расшифровать и проверить подпись. Приложение и клавиатура работают с криптографией только через неё.

## Пользовательские истории
- Как отправитель, я хочу, чтобы сообщение мог прочитать только выбранный собеседник и я сам, чтобы мессенджер и посторонние видели лишь шифротекст.
- Как получатель, я хочу знать, от кого сообщение и что его не изменили по дороге.
- Как разработчик приложения и клавиатуры, я хочу простой API без криптопримитивов, чтобы нельзя было ошибиться в их использовании.

## Критерии приёмки
- AC1: `Identity.generate()` создаёт личность из ключа согласования X25519 и ключа подписи Ed25519 (CryptoKit). Две генерации дают разные ключи.
- AC2: Открытый ключ личности выгружается в одну строку `ckpub1:<base64url>` (обе публичные части) и разбирается обратно в равный ключ. Отпечаток — первые 16 байт SHA-256 от публичных частей, 8 групп по 4 hex-символа в верхнем регистре через пробел.
- AC3: `seal(_ text:, from:, to:)` возвращает одну строку `ckmsg1:<base64url>` без пробелов и переводов строк. Исходный текст не встречается в ней ни как подстрока, ни в base64.
- AC4: Каждый получатель и сам отправитель расшифровывают строку и получают исходный текст байт в байт — кириллица, составные эмодзи, переводы строк.
- AC5: Личность, которой нет среди получателей, получает ошибку `notARecipient`, а не мусор.
- AC6: Изменение любого байта сообщения → ошибка `tampered` (испорченный формат — `malformed`). Частично расшифрованный текст не возвращается никогда.
- AC7: Результат расшифровки содержит открытый ключ отправителя и вердикт: `verified(contact)`, если отправитель есть в переданном списке контактов, `unknownSender(fingerprint)`, если подпись верна, а отправителя в списке нет. Подменить отправителя (переподписать своим ключом, оставив чужой ключ отправителя) нельзя — ошибка `tampered`.
- AC8: Два шифрования одного и того же текста дают разные строки.
- AC9: Пробелы и переводы строк в любом месте строки при разборе игнорируются. Неверный префикс, обрезанная строка → `malformed`; неизвестная версия (`ckmsg2:`) → `unsupportedVersion`.
- AC10: Пустой текст → `emptyMessage`; больше 4096 байт UTF-8 → `messageTooLong`; пустой список получателей → `noRecipients`. Шифротекст 100 символов кириллицы для одного получателя (плюс себя) — не длиннее 800 символов.
- AC11: `String(describing:)`, `print` и `dump` личности не выводят приватные ключи; приватная часть отдаётся только явным методом для сохранения в Keychain.

## Состояния экрана
Экрана нет (ui: no) — проверяется автотестами `scripts/test.sh core`.

## Граничные случаи
- Ровно 4096 и 4097 байт; текст из одних пробелов (разрешён, это содержимое); один символ.
- Получатель — я сам; один и тот же получатель дважды (шифруется один раз).
- Строка, вставленная с пробелами и переносом посередине; строка без префикса; base64 с паддингом `=` и без.
- Открытый ключ с неверной длиной, с чужим префиксом, «нулевой» ключ X25519.

## Не входит
- Совместимость с OpenPGP, шифрование по паролю, сжатие, вложения.
- Прямая секретность и обновляемые сессии (как в Signal) — у нас статические ключи.
- Хранение ключей и контактов (02, 03) — ядро работает с переданными ему значениями.

## Решения, принятые без пользователя
- Схема: случайный ключ сообщения шифрует текст (ChaCha20-Poly1305); для каждого получателя ключ сообщения заворачивается через эфемерный X25519 + HKDF-SHA256 с доменной строкой `CipherKeyboard v1`; подпись Ed25519 покрывает заголовок, список получателей и шифротекст.
- Сообщение всегда включает отправителя в число получателей — это делает вызывающий код (06), ядро просто принимает список.
- Тесты — Swift Testing в `Packages/CipherCore/Tests`, с фиксированными векторами для разбора формата.

## Открытые вопросы
