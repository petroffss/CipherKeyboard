# Форматы CipherCore: `ckpub1` и `ckmsg1`

Описание байтовой раскладки открытого ключа и сообщения версии 1. Реализация — `Sources/CipherCore`
(`PublicKey.swift`, `Envelope.swift`, `CipherMessage.swift`, `TextEncoding.swift`). Любое изменение раскладки,
доменной строки, AAD или того, что подписывается, — новая версия (`ckpub2`, `ckmsg2`); тест `GoldenVectorTests`
ломается, если формат поменяли без смены версии.

Обозначения: `‖` — конкатенация байт; все многобайтовые числа — big-endian; длины — в байтах.

## Текстовая обёртка (общая для обоих форматов)

- Текст: `<префикс><версия>:` + **base64url без паддинга** (RFC 4648 §5, алфавит `A–Z a–z 0–9 - _`).
- Кодирование на выходе: без `=`, без пробелов и переводов строк.
- Разбор строгий и канонический: символ не из алфавита, длина `≡ 1 (mod 4)` или ненулевые неиспользуемые биты
  в последнем символе (неканоническая запись тех же байт) — ошибка.
- Перед разбором удаляются все символы `CharacterSet.whitespacesAndNewlines` в любом месте, включая префикс
  (пробел, `\t`, `\n`, `\r`, неразрывный пробел U+00A0, U+2028 и т. п.).

## `ckpub1` — открытый ключ

```
"ckpub1:" ‖ base64url( X25519_pub[32] ‖ Ed25519_pub[32] )        = 7 + 86 = 93 символа
```

| Смещение | Длина | Поле |
|---:|---:|---|
| 0 | 32 | публичный ключ согласования X25519 (raw, как `Curve25519.KeyAgreement.PublicKey.rawRepresentation`) |
| 32 | 32 | публичный ключ подписи Ed25519 (raw, как `Curve25519.Signing.PublicKey.rawRepresentation`) |
| | **64** | всего |

Разбор `PublicKey(string:)`, по порядку:
1. Удалить все `whitespacesAndNewlines`.
2. Строка должна начинаться с `ckpub<цифры>:` с позиции 0, иначе `invalidKey` (текст вокруг, чужой префикс,
   `ckmsg1:…`, пустая строка). Цифры не `1` → `unsupportedVersion`.
3. Снять с конца паддинг `=` (допускается только корректный: 1–2 символа, общая длина кратна 4).
4. Тело — ровно 86 символов, строгий канонический base64url → ровно 64 байта, иначе `invalidKey`.
5. Часть X25519 не должна быть точкой малого порядка (нулевая точка, `01 00…00` и другие): проверяется
   согласованием с фиксированным скаляром — с такой точкой общий секрет нулевой, CryptoKit его отвергает →
   `invalidKey`.

**Отпечаток:** первые 16 байт `SHA-256(X25519_pub ‖ Ed25519_pub)` (те же 64 байта), в hex верхнего регистра,
8 групп по 4 символа через один пробел — 39 символов, например `3CE9 D861 1272 B2A6 0720 1589 E865 3A98`.
`short` — первые 2 группы (9 символов).

**Приватные данные личности** (`privateKeyData()`, только для Keychain, в сообщения не попадают):
`X25519_priv[32] ‖ Ed25519_priv[32]` = 64 байта.

## `ckmsg1` — сообщение

```
"ckmsg1:" ‖ base64url( сообщение[T] )
T = 192 + 48·n + L
```

где `n` — число записей получателей (1…16), `L` — длина открытого текста в байтах UTF-8 (1…4096).

| Смещение | Длина | Поле |
|---:|---:|---|
| 0 | 1 | версия формата = `0x01` |
| 1 | 1 | `n` — число записей получателей, 1…16 |
| 2 | 2 | `L` — длина открытого текста в байтах, UInt16 big-endian, 1…4096 |
| 4 | 64 | ключ отправителя: `X25519_pub[32] ‖ Ed25519_pub[32]` (как в `ckpub1`) |
| 68 | 32 | эфемерный публичный X25519 `E_pub` (новый для каждого сообщения, общий для всех записей) |
| 100 | 48·n | записи получателей, каждая — `wrapped_key[32] ‖ tag[16]` |
| 100+48n | 12 | nonce ChaCha20-Poly1305 для текста (случайный) |
| 112+48n | L | шифротекст текста |
| 112+48n+L | 16 | тег Poly1305 текста |
| 128+48n+L | 64 | подпись Ed25519 |
| | **192+48n+L** | всего |

Заголовок — первые 4 байта (версия, `n`, `L`): по ним известна полная длина `T`, поэтому сообщение
самоограничено — текст сразу после него (`…ok`, `… спасибо`, второе сообщение) не мешает разбору.

Пример — золотой вектор из `Tests/CipherCoreTests/GoldenVectorTests.swift`: заголовок `01 02 00 3E` → `n = 2`
(B и сам A), `L = 62`, `T = 192 + 96 + 62 = 350` байт = 467 символов base64url, вместе с префиксом 474.

Записи получателей не содержат ни ключей, ни отпечатков получателей — по сообщению не видно, кому оно.
Ключ отправителя виден всем (нужен для проверки подписи). Порядок записей: получатели из `to` в порядке
передачи, затем отправитель; повторы (одинаковая часть X25519) и отправитель в `to` дают одну запись.

### Константы

- Доменная строка `D` = UTF-8 `"CipherKeyboard v1"` (17 байт).
- Nonce записи получателя — 12 нулевых байт (ключ записи одноразовый: выводится из нового эфемерного ключа).

### Шифрование (`seal`)

1. `K` — случайный 32-байтный ключ сообщения; `E` — новая эфемерная пара X25519.
2. Для каждого получателя `R` (публичный X25519 `R_x`):
   - `ss = X25519(E_priv, R_x)`;
   - `KEK = HKDF-SHA256(ikm = ss, salt = пусто, info = D ‖ E_pub[32] ‖ R_x[32], длина = 32)`;
   - запись = `ChaCha20-Poly1305(key = KEK, nonce = 0¹², plaintext = K, aad = пусто)` → `wrapped_key[32] ‖ tag[16]`.
3. Текст: `ChaCha20-Poly1305(key = K, nonce = случайный[12], plaintext = UTF-8 текста, aad = AAD)`.
4. Подпись: `Ed25519.sign(sender_priv, D ‖ байты[0 ..< T−64])`.

**AAD шифрования текста** = байты `[0 ..< 100+48n]`: версия, `n`, `L`, **ключ отправителя**, `E_pub`, все записи
получателей. Ключ отправителя в AAD привязывает текст к отправителю: если заменить ключ отправителя и
переподписать сообщение своим ключом, запись получателя всё ещё раскроется, но текст — нет (`tampered`).

**Подпись** покрывает `D ‖` все байты сообщения до подписи: заголовок, ключ отправителя, эфемерный ключ, записи
получателей, nonce, шифротекст и тег. Проверяется ключом Ed25519 из поля «ключ отправителя».

### Разбор (`open`), порядок проверок

1. **Поиск.** Удалить все `whitespacesAndNewlines`; найти первое вхождение `ckmsg<цифры>:`. Нет → `noMessage`.
   Цифры не `1` (`ckmsg2:`, `ckmsg10:`) → `unsupportedVersion`.
2. **Формат** (`malformed`). Из символов base64url сразу после префикса декодировать первые 8 → заголовок;
   версия `0x01`, `1 ≤ n ≤ 16`, `1 ≤ L ≤ 4096`, иначе `malformed`. Из заголовка — `T` и нужное число символов
   `⌈4T/3⌉` (не больше 6742 при максимальных `n` и `L`; больше 20 000 символов не читается никогда).
   Если подряд идущих символов base64url меньше — `malformed` (обрезано, `*` внутри); ровно столько символов
   декодируются строго и канонически, остальное (паддинг `=`, текст после) игнорируется. Ключ отправителя
   проходит те же проверки, что `ckpub1` (точка малого порядка → `malformed`).
3. **Подпись** (`tampered`). Ed25519 ключом отправителя из сообщения над `D ‖ байты[0 ..< T−64]`.
4. **Своя запись** (`notARecipient`). `ss = X25519(own_priv, E_pub)`, `KEK` как при шифровании с
   `R_x = own X25519 pub`; перебрать все `n` записей, первая, что раскрылась, даёт `K`. Ни одной →
   `notARecipient` (подпись к этому моменту верна, поэтому порча любого байта даёт `tampered`, а не
   `notARecipient`).
5. **Текст** (`tampered`). ChaCha20-Poly1305 с `K`, nonce и AAD из сообщения. Не сошлось → `tampered`.
   Текст не валидный UTF-8 → `malformed`. Частично расшифрованный текст не возвращается никогда.
6. **Отправитель.** Ключ отправителя (все 64 байта) равен ключу личности → `.me`; равен ключу контакта →
   `.contact`; иначе `.unknown(отпечаток)`.
