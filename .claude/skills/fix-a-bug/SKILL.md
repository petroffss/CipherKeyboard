# /fix-a-bug — сначала доказать, потом чинить

Баг: $ARGUMENTS

Никаких правок «на глаз»: что не воспроизведено, то не чиним.

## 1. Понять
- Не хватает шагов воспроизведения или ожидаемого поведения — задай один вопрос и жди.
- Определи фичу (`specs/*`), к которой относится баг, и её риск.

## 2. Ветка
`git status --porcelain` пуст (иначе спроси). `git switch main && git switch -c fix/<кратко>`.

## 3. Воспроизвести
- Пройди шаги сам (браузер или команда) — убедись, что видишь то же, что пользователь.
- Закрепи воспроизведение автотестом, который **сейчас падает** (или командой, если тест невозможен). Это и доказательство, и будущая защита.
- Не воспроизводится — остановись, расскажи, что пробовал, спроси детали.

## 4. Причина
- Гипотеза одной фразой: «X происходит, потому что Y в файл:строка».
- Проверка: гипотеза подтверждена, только если изменение предполагаемой причины меняет результат воспроизведения. Не подтвердилась — следующая гипотеза.

## 5. Когда сломалось (если раньше работало)
- Рабочие версии: `git log --oneline --grep='^\[ok\]'`.
- Найди последнюю, где воспроизведение проходит, затем `git bisect start <плохой> <хороший>` и `git bisect run <команда воспроизведения>`; в конце `git bisect reset`.
- Баг был всегда — так и скажи: требования или evals его не покрывали.

## 6. Отчёт до исправления (коротко)
Симптом → причина (файл:строка) → виновный коммит и фича → риск по таблице `classify-risk` → варианты:
- **исправить вперёд** — обычный путь;
- **откатить фичу целиком**: `git revert -m 1 <sha merge-коммита>` — если баг high (деньги, данные, вход) и исправление не тривиально: сначала откат, потом спокойное исправление.
High — спроси пользователя (AskUserQuestion). Low/medium — исправляй вперёд.

## 7. Исправить
- Чини первопричину, не симптом.
- Найди тот же класс ошибки в других местах (`grep`) и исправь там тоже.
- Воспроизведение теперь проходит; прогони все тесты, линтер, типы (команды в CLAUDE.md). Покажи вывод.
- Коммит: `[ok] fix(<фича>): <что исправлено>`.

## 8. Баг → eval
- В `specs/<фича>/evals.md` добавь eval с тегом `[regression]`: шаги — шаги воспроизведения, ожидание — правильное поведение, статус `pending`.
- Запусти `Agent(subagent_type: "verifier")` только на этот eval — статус `pass` ставит он (хук не даст тебе).
- Коммит `[ok] evals(<фича>): регрессия <кратко>`.

## 9. Почему ревью пропустило
Предложи одну строку для REVIEW.md → «Выученные правила» (формат там) и спроси пользователя. Добавь только с одобрения.

## 10. Слияние
Спроси пользователя → `git switch main && git merge --no-ff fix/<кратко> -m "[ok] fix: <кратко>"`. Сообщи sha и как откатить: `git revert -m 1 <sha>`.
