# /first-time-user — свежий взгляд

Цель проверки: $ARGUMENTS — id фичи или `all` (главные сценарии продукта).

Ты знаешь, как устроено приложение, поэтому многое пропустишь. Агент `first-time-user` не знает ничего: код, файлы и терминал ему закрыты хуком, CLAUDE.md он не получает. Твоя задача — дать ему только то, что получил бы живой новый клиент.

## 1. Цели — языком клиента
- Для фичи: из «Сути» и «Пользовательских историй» в requirements.md сформулируй 1–3 цели, как их сказал бы человек: «записаться на стрижку на завтра после шести».
- Для `all`: главные сценарии из IDEA.md.
- Никаких технологий, названий компонентов, роутов (кроме стартового адреса), подсказок о том, где что лежит.

## 2. Песочница
- Запусти команду «Песочница» из CLAUDE.md — приложение с чистыми данными (веб — временная БД; мобильные — новый симулятор или эмулятор с установленным приложением). Нет такой команды — настрой её или спроси пользователя. Реальные данные не трогаем. Долгий запуск — в фоне.
- Убедись, что приложение готово: веб — `curl -s -o /dev/null -w "%{http_code}" <URL>`; мобильные — приложение установлено и открыто на стартовом экране (скриншот симулятора).
- Если для цели нужен готовый аккаунт или данные — создай их в песочнице (сид, API, тестовые данные) и передай агенту как «тебе дали логин и пароль».

## 3. Агент
`Agent(subagent_type: "first-time-user")`. Промпт — только: стартовая точка (адрес или «приложение открыто на симуляторе <устройство>»), цели, данные для входа (если нужны) и «ты видишь это приложение впервые». Дождись отчёта.
Агенту доступны только инструменты экрана: сборку, установку и перезапуск приложения хук ему запрещает — это твоя работа.

## 4. Уборка
Останови песочницу и удали её данные (временную БД, симулятор).

## 5. Отчёт
- Сохрани отчёт агента с датой: `specs/<фича>/ftue-report.md` (для `all` — `specs/_ftue/<ГГГГ-ММ-ДД>.md`).
- Разбери каждую находку (тут тебе нужен код): причина — файл:строка, что исправить, серьёзность. Группы: **блокеры** (не смог дойти до цели), **путаница** (дошёл с трудом), **косметика**.

## 6. Что исправлять — решает пользователь
AskUserQuestion (multiSelect): какие находки исправить. Для выбранных:
- нарушено существующее требование → `/fix-a-bug`;
- нужно новое поведение → новый eval (`pending`) в evals.md, фича обратно в `in-review` (`set-status <фича> in-review`) → `/approve` → `/review-loop`;
- тексты и подсказки (low) → правка на ветке `fix/ftue-<фича>`, тесты и линтер, коммит `[ok]`.
