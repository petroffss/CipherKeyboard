# Evals: Название фичи

> Контракт приёмки. Фича готова, только когда **все** evals в статусе `pass`.
> Статусы ставит только агент verifier, с доказательством. Строитель этот файл не меняет.
> Формат проверяет хук: заголовок `## E<номер> · Название [теги]`, поля `- **Ключ:** значение`.
> Типы: browser · test · command · design · api. Статусы: pending · pass · fail.
> Теги: [negative] ошибки и неверный ввод · [security] права и чужие данные · [design] сравнение с макетом ·
> [mobile] узкий экран 375px · [regression] баг, который уже был.

## E1 · Пользователь видит свои задачи после входа
- **Тип:** browser
- **Шаги:** 1) открыть /login 2) войти как demo@example.com / demo-pass 3) перейти на /tasks
- **Ожидается:** заголовок «Мои задачи», ровно 3 задачи из тестовых данных, отсортированы по сроку (ближайший сверху)
- **Почему провалит плохую работу:** ловит статичную заглушку вместо данных из БД и забытую сортировку
- **Статус:** pending
- **Доказательство:** —

## E2 · Задача сохраняется после обновления страницы
- **Тип:** test
- **Шаги:** автотест `tests/tasks.test.ts › creates task and reads it back` — создать задачу через API, перечитать список
- **Ожидается:** тест проходит; задача в ответе с теми же полями
- **Почему провалит плохую работу:** ловит хранение в памяти вместо БД
- **Статус:** pending
- **Доказательство:** —

## E3 · Пустое название не сохраняется [negative]
- **Тип:** browser
- **Шаги:** на /tasks нажать «Добавить», оставить поле пустым, нажать «Сохранить»
- **Ожидается:** задача не создана, под полем текст «Введите название», фокус на поле
- **Почему провалит плохую работу:** ловит отсутствие валидации и молчаливые ошибки
- **Статус:** pending
- **Доказательство:** —

## E4 · Чужую задачу нельзя открыть по ссылке [security]
- **Тип:** api
- **Шаги:** войти как user-a, запросить GET /api/tasks/<id задачи user-b>
- **Ожидается:** 404 (не 403 и не данные задачи)
- **Почему провалит плохую работу:** ловит проверку только «вошёл ли», без проверки владельца
- **Статус:** pending
- **Доказательство:** —

## E5 · Совпадает с макетом [design]
- **Тип:** design
- **Шаги:** открыть /tasks и mockup.html (состояние «Список»), ширина 1280px
- **Ожидается:** те же блоки в том же порядке, те же тексты кнопок и заголовков, цвета акцентов; отличия рендеринга шрифта до 2px допустимы
- **Почему провалит плохую работу:** ловит «примерно похоже» и пропущенные элементы
- **Статус:** pending
- **Доказательство:** —

## E6 · Мобильный вид [design] [mobile]
- **Тип:** design
- **Шаги:** то же при ширине 375px, сравнить с мобильной рамкой макета
- **Ожидается:** нет горизонтальной прокрутки, кнопки не меньше 44px, порядок блоков как в макете
- **Почему провалит плохую работу:** ловит десктопную вёрстку, «сжатую» на телефоне
- **Статус:** pending
- **Доказательство:** —
