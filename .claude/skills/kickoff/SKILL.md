# /kickoff — из задумки в готовый к работе проект

Задумка: $ARGUMENTS

Результат скилла: заполненные IDEA.md, CLAUDE.md, REVIEW.md; черновики фич в `specs/`; каркас приложения, где работают команды запуска, тестов и линтера; первый коммит. **Фичи не строй** — их строит `/review-loop` после одобрения evals.

## 0. Проверка
- Если в CLAUDE.md нет пометок `⟨…⟩` и в `specs/` уже есть фичи — проект уже запущен. Спроси (AskUserQuestion): добавить новые фичи (тогда для каждой — `/write-evals <имя> <описание>`) или начать заново. Не перезаписывай молча.

## 1. Задумка
- Источник: аргумент выше и/или раздел «Задумка» в IDEA.md. Если оба пусты — попроси описать идею парой абзацев и остановись.
- Если задумка пришла аргументом — запиши её дословно в IDEA.md, раздел «Задумка» (вместо `⟨впиши сюда⟩`).

## 2. Уточнение — только то, что меняет архитектуру
Один вызов AskUserQuestion, не больше 4 вопросов, у каждого первый вариант — рекомендуемый. Кандидаты:
- Платформа: веб / мобильное / десктоп / CLI / бот.
- Аккаунты: нужны ли вход и данные, которые видит только владелец.
- Деньги и внешние действия: оплата, письма, интеграции.
- Стек: если у пользователя нет предпочтений — предложи самый скучный и проверенный для задачи и окружения.
Всё остальное реши сам и запиши в IDEA.md → «Решения, принятые на старте».

## 3. Окружение
- Проверь, что есть для выбранного стека: `which node npm python3 go docker git` и т.п.
- Чего-то не хватает — скажи, что и как установить (одна команда на строку). Системные пакеты без согласия не ставь.

## 4. IDEA.md
Заполни разделы под чертой: проблема, для кого, главные сценарии, MVP, что не входит, решения на старте, открытые вопросы.

## 5. Фичи
- 3–10 фич для MVP. Каждая — законченная польза, которую можно проверить из интерфейса или командой; размер — на один `/review-loop` (несколько экранов или эндпоинтов, не «весь бэкенд»).
- Порядок — по зависимостям. Папка `specs/NN-kebab-name/` (`01-`, `02-`, …, латиницей).
- Для каждой — `requirements.md` по шаблону [../write-evals/templates/requirements.md](../write-evals/templates/requirements.md), `status: draft`. Заполни суть, истории, черновые критерии приёмки, состояния экрана, граничные случаи, что не входит, `depends_on`.
- Риск каждой фичи оцени по правилам из [../classify-risk/SKILL.md](../classify-risk/SKILL.md) (прочитай файл, примени таблицу прямо здесь) и запиши `risk` и `risk_reason`.
- Evals и макеты здесь не пиши — их делает `/write-evals` по одной фиче, с ревью пользователя.
- В IDEA.md → «MVP» — список фич со ссылками на их папки.

## 6. CLAUDE.md и REVIEW.md
- CLAUDE.md: замени все `⟨…⟩`, удали строку-подсказку про `/kickoff` в шапке. Раздел «Как мы работаем» не трогай. Файл держи коротким (до ~80 строк). Ни одного символа `⟨` остаться не должно — по нему хук начала сессии понимает, что проект не инициализирован.
- REVIEW.md: заполни все `⟨…⟩`: что значит «провал» именно в этом продукте (2–5 конкретных пунктов), зоны high-риска под проект, пути для игнора, особые способы проверки. «Выученные правила» оставь пустым.

## 7. Каркас приложения
- Минимальное приложение на выбранном стеке: одна стартовая страница или команда, один smoke-тест, линтер, форматтер.
- **Песочница**: способ запустить приложение на пустой временной БД (например, путь к БД через переменную окружения во временную папку), чтобы `/first-time-user` и verifier не трогали реальные данные.
- Прогони каждую команду из таблицы «Команды» и покажи вывод. Команда, которая не сработала, в CLAUDE.md не попадает — сначала почини.
- Если у стека есть форматтер — добавь в `.claude/settings.json` PostToolUse-хук форматирования (matcher `Edit|Write`), сохранив существующие хуки.
- `.gitignore`: допиши строки под стек, не удаляя строки шаблона.

## 8. Git
- Нет репозитория — `git init -b main`.
- Коммит: `[ok] kickoff: каркас, требования, правила ревью`.

## 9. Итог пользователю (коротко)
- Что за продукт (2 строки) и стек.
- Таблица фич — вывод `python3 .claude/scripts/pipeline.py`.
- Решения, принятые без пользователя, списком — чтобы их можно было поправить.
- Открытые вопросы, если есть.
- Следующий шаг: `/write-evals 01-…`.
