## Как мы работаем
Не менять без причины — на этом держатся скиллы и хуки в `.claude/`.

**Конвейер фичи** (статусы в `specs/<фича>/requirements.md`):
`/write-evals` → пользователь смотрит evals и макет → `/approve` → `/review-loop` → (medium/high: `/approve`) → готово.
Статусы: `draft → in-review → approved → building → verified → done`. Где мы сейчас — `/pipeline`.

1. **Сначала контракт, потом код.** Код фичи пишется только после того, как пользователь одобрил её evals (`approved`). Одобряет только пользователь — командой `/approve`.
2. **Доказательство, а не «готово».** Никогда не говори, что сделано, без вывода тестов/команд или того, что видно в браузере. Фича готова, только когда все её evals в статусе `pass` — это проверяют хуки.
3. **Строит один, проверяет другой.** Строитель (`builder`), проверяющий (`verifier`) и ревьюер (`reviewer`) — разные агенты в свежих контекстах. Статус `pass` у eval ставит только verifier.
4. **Строгость по риску.** Перед evals каждая фича получает риск (`/classify-risk`): low / medium / high. Чем выше риск, тем больше evals, глубже ревью и обязательнее приёмка человеком.
5. **Повторяющаяся ошибка → правило.** Если ревью находит одно и то же или баг проскочил — предлагай одну строку в REVIEW.md → «Выученные правила». Добавляй только с одобрения пользователя.
6. **Баг** → `/fix-a-bug`: воспроизвести → доказать причину → исправить → регрессионный eval.
7. **Свежий взгляд** → `/first-time-user <фича>`: агент без доступа к коду проходит приложение как новый клиент (для high обязательно).
8. **Мелкая правка** (опечатка, текст, цвет) — можно без цикла: правка → тесты и линтер → коммит `[ok]`. Всё, что меняет поведение, — через фичу или `/fix-a-bug`.

**Git** (обязателен — на нём держится откат):
- `main` всегда рабочий. Фича — ветка `feature/<id фичи>`, багфикс — `fix/<кратко>`.
- Каждая рабочая версия (тесты и линтер зелёные) — коммит с префиксом `[ok]`; незавершённое — `[wip]`. По `[ok]`-коммитам `/fix-a-bug` ищет, где сломалось.
- В `main` фича попадает одним merge-коммитом `git merge --no-ff`, поэтому откат всей фичи — одна команда: `git revert -m 1 <sha>`.
- Нельзя без явной просьбы пользователя: `push --force`, `reset --hard`, переписывание истории `main`, удаление веток.
